# 需求可行性分析报告

> 分析日期：2026-05-13
> 项目：OpenMAIC (Open Multi-Agent Interactive Classroom)
> 当前版本：v0.2.1

---

## 一、项目现状概要

| 维度 | 现状 |
|---|---|
| **技术栈** | Next.js 16 (App Router) + React 19 + TypeScript 5 + Tailwind CSS 4 + Zustand + Dexie (IndexedDB) + LangGraph |
| **数据层** | 浏览器 IndexedDB（主要，通过 Dexie） + 服务器端 `data/` JSON 文件（次要用作服务端持久化） |
| **认证系统** | 仅 `ACCESS_CODE` 全站级 HMAC 密码保护，**无用户概念**，无注册/登录/会话 |
| **用户角色** | 不存在。仅 AI Agent 数据模型中有 `role: 'teacher' | 'assistant' | 'student'` 作为智能体身份标识 |
| **数据库** | 无 PostgreSQL / Supabase / Prisma / Drizzle 等任何关系型数据库依赖 |
| **媒体存储** | 客户端 IndexedDB（主要）+ `lib/storage/` 有抽象 `StorageProvider` 接口 + 空实现 `NoopStorageProvider` |
| **TTS** | 已集成多家供应商（OpenAI / MiniMax / Azure / GLM / Qwen / ElevenLabs / VoxCPM），支持声音选择和克隆 |
| **课程模型** | AI 一次性生成，以 `Stage` + `Scene` 结构存储，非持久化课程管理 |
| **部署方式** | Vercel / Docker / `pnpm dev`，配置驱动 |

### 核心定位

OpenMAIC 是一个 **AI 多智能体互动课堂内容生成引擎**：
- 输入主题 → AI 生成课件 + 授课 + 互动
- 一次性消费型体验，而非持续性教务管理
- 所有数据存储在用户浏览器本地

## 二、逐项可行性分析

### 1. 4 角色认证系统（admin / teacher / school_student / mature_student）

**可行性：🔴 低**

| 分析项 | 详情 |
|---|---|
| **当前差距** | 无用户模型、无密码哈希、无会话管理、无注册登录流程、无角色枚举、无 RBAC 中间件 |
| **必需新增** | ① 数据库（用户表 + role 字段） ② Auth 库（NextAuth.js / Lucia / Clerk） ③ 注册/登录页面 ④ 角色守卫中间件 ⑤ 密码重置/邮箱验证 |
| **影响范围** | `middleware.ts`、`app/api/` 全部路由、页面路由、数据模型、构建配置 |
| **兼容风险** | 现有 ACCESS_CODE 逻辑需保留或迁移；现有匿名用户数据（IndexedDB）无关联用户ID |
| **预估工期** | 2-4 周（含测试） |

> **结论**：这是从"无用户"到"完整 IAM"的架构跃迁，是整个需求集中影响最大、前置依赖最多的一项。

### 2. 教师仪表盘（学生管理 / 课程分配 / 分析）

**可行性：🔴 低**

| 分析项 | 详情 |
|---|---|
| **前置依赖** | 必须完成 #1（角色系统）+ 数据库 + 学生-教师关系模型 |
| **当前差距** | 无"教师"概念、无"学生管理"、无"课程分配"、无"分析数据" |
| **必需新增** | ① 教师专属路由 `/dashboard/teacher/` ② 学生列表 + CRUD API ③ 课程分配逻辑 ④ 统计看板（图表 + 聚合查询） |
| **预估工期** | 3-5 周（依赖 #1 完成后） |

---

### 3. 管理员仪表盘（用户管理 / 平台统计）

**可行性：🔴 低**

| 分析项 | 详情 |
|---|---|
| **前置依赖** | 必须完成 #1（角色系统）+ #2（用户管理基础） |
| **当前差距** | 无管理员概念、无平台级统计数据采集 |
| **必需新增** | ① 管理员路由 `/dashboard/admin/` ② 用户管理（列表/禁用/角色变更） ③ 平台统计（课程数、活跃用户、使用量等） |
| **预估工期** | 2-3 周（依赖 #1/#2 完成后） |

---

### 4. 年级体系（Grade 1-12，江苏版对齐）

**可行性：🟡 中**

| 分析项 | 详情 |
|---|---|
| **当前差距** | 无年级概念，课程模型 `StageRecord` 仅有 `name/description/style` 等字段 |
| **实现路径** | 在课程/场景模型上增加 `grade`（1-12）和 `syllabus`（江苏版）字段；生成阶段可传入年级约束指导 AI 内容难度 |
| **亮点** | 可同时作为内容生成的 prompt context（"针对 Grade 8 江苏版"），提升 AI 输出质量 |
| **预估工期** | 1-2 周（纯数据层 + UI 筛选） |

> **注意**：江苏版对齐意味着需要维护教材知识点映射表，这本身是一个持续性的数据工程工作。

---

### 5. 跨设备媒体服务（服务器端存储图片和音频）

**可行性：🟢 高** ✅

| 分析项 | 详情 |
|---|---|
| **当前基础** | `lib/storage/` 已有 `StorageProvider` 接口 + `NoopStorageProvider` + `proxy-media` API 端点 |
| **实现路径** | ① 实现真实 StorageProvider（S3 / 阿里云OSS / 本地文件系统） ② 上传 IndexedDB 中已有媒体到服务器 ③ 替换 `proxy-media` 逻辑 ④ 确保 classroom JSON 中的 media URL 正确 |
| **影响范围** | 仅限于存储层，不影响现有 UI 和业务流程 |
| **预估工期** | 1-2 周 |

---

### 6. 课程持久化到 PostgreSQL / Supabase

**可行性：🟡 中**

| 分析项 | 详情 |
|---|---|
| **当前差距** | 数据目前在浏览器 IndexedDB + 服务器 JSON 文件，无 ORM、无 schema 迁移、无服务端查询能力 |
| **实现路径** | ① 引入 `supabase-js` 或 `drizzle-orm` ② 设计数据库 schema（stages, scenes, agents, audio_refs, media_refs, chat_sessions, quiz_results） ③ 编写数据迁移脚本 ④ 修改 `classroom-storage.ts` 和 API 路由从 DB 读写 ⑤ 可选：将 IndexedDB 降级为离线缓存 |
| **技术风险** | 现有数据（IndexedDB）需迁移策略；部分数据（Blob 媒体）体积大需联动 #5 |
| **预估工期** | 2-4 周 |

> **建议**：结合 #5 一并实施，Supabase 可同时提供 PostgreSQL + 对象存储 + Auth，三个需求一次覆盖。

## 四、核心矛盾与路线建议

### 根本矛盾

**OpenMAIC 当前定位**：AI 内容生成引擎 → "describe → AI generates → learn → done"
**需求隐含定位**：传统 LMS → "register → enroll → manage courses → track progress"

前者是一次性消费体验，后者是持续性管理平台。两者可以结合，但路线选择影响巨大。

### 两条技术路线

| 路线 | 描述 | 投入 |
|---|---|---|
| **路线 A：轻量叠加** | 保留 OpenMAIC 核心不变，在边缘加用户/持久化。适合快速验证。 | 1-2 月 |
| **路线 B：重构融合** | 引入 Supabase 全家桶（Auth + DB + Storage），将 OpenMAIC 重构为以 LMS 为核心的平台，AI 生成作为"课程创建引擎"模块。 | 3-6 月 |

### 建议实施顺序

```
Phase 1（快速见效，1-2 周）
  ├── 7. 学科分类与筛选
  ├── 8. 个人资料 + TTS 声音
  └── 5. 跨设备媒体服务器

Phase 2（基础设施，2-4 周）
  ├── 6. PostgreSQL / Supabase 集成
  └── 4. 年级体系

Phase 3（LMS 核心，1-2 月）
  ├── 1. 4 角色认证系统
  ├── 2. 教师仪表盘
  └── 3. 管理员仪表盘
```

### 关键问题待澄清

1. **AI 生成内容是否应作为"课程"长期保存？** 还是每次 AI 重新生成？这决定持久化模型的复杂性。
2. **年级和江苏版对齐** 是否只用作 AI prompt context（控制内容难度和范围），还是需要维护完整的教材知识点映射？
3. **4 种角色中 `mature_student` 与 `school_student` 的实质差异是什么？** 这将影响 RBAC 权限模型设计。
